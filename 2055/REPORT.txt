Measurement
The same measure.py was run against separately built source checkouts:
the unmodified base and the fixed version. CPU and one CUDA GPU were
measured, with separate compilation caches. Each version has 532 rows:
51 FP16 matrices and 41 matrices per other dtype, each on two backends
and with two calling forms. Repeated calling forms are counted as
separate evaluations, not independent random samples.

Before: 356/532 evaluations passed. There were 176 FP16 failures:
144 with nonfinite factors and 32 finite but inaccurate results.
After: 532/532 passed. On each backend, FP16 improved from 14/102
passing evaluations to 102/102. Measured FP32/64 rows are identical
before and after the change.

Error definitions
All error measurements use the returned factors promoted to NumPy
float64, against the input rounded to the tested dtype.
- Reconstruction: max abs(U diag(sigma) V^T - A).
- Scale-relative reconstruction: reconstruction / max abs(A); zero
  input is reported as zero error.
- Error allowance: tol * max abs(A) + 2 * dtype smallest subnormal.
  Tolerances are 5e-3, 1e-5, 1e-12 for FP16, FP32, FP64 respectively.
- Error-budget ratio: reconstruction / allowance; <= 1 passes.
- Orthogonality: max entrywise error over U^T U - I and V^T V - I.

The largest FP16 error-budget ratio after the fix is 0.165485;
maximum orthogonality error is 5.70086e-4. At subnormal input scales,
the largest scale-relative reconstruction error is 1.0021%; the
absolute output-quantization allowance is necessary there. These
results do not establish correctness for every possible finite input.
Outputs that exceed the FP16 representable range are not in this set.

Existing validation
The new unittest regressions had 176 failing subcases on the base,
then all 12 tests passed with the fix. All 170 tests in the full matrix
module passed on CPU/CUDA. Native builds and applicable pre-commit
checks passed. Test command: uv run --extra dev -m unittest warp.tests.matrix.test_mat -v. No performance
or timing comparison is claimed.

Files
before.csv / after.csv: every measured evaluation; blank metric fields
indicate nonfinite factors, not zero error.
summary.csv: per-device/dtype summary.
svd3-validation.png / .svg: raster and editable vector figures.
measure.py / plot.py: reproducible measurement and figure generation.
SHA256SUMS: SHA-256 checksums for this asset set.

To reproduce, run measure.py from each built source checkout with that
checkout on PYTHONPATH, a distinct --cache directory, --phase before or
after, and the matching --output CSV filename. Use uv run --no-project
--with numpy. Run plot.py with uv run --no-project --with numpy --with
matplotlib in an environment with both CSV files beside the script.
